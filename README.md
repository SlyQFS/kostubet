# Kostubet GitHub & APK Watcher Telegram Bot 🚀 (v1.0.0)

Высокопроизводительный асинхронный Telegram-бот на Rust (**teloxide** + **SQLite**), предназначенный для автоматического отслеживания релизов GitHub-репозиториев, управления каталогом кастомных APK-приложений, интерактивной модерации заявок и публикации оформленных карточек релизов с доставкой APK-файлов документами в каналы и форумные топики супергрупп.

---

## ✨ Особенности и архитектура

- **Диспетчеризация и FSM-диалоги (`dptree`)**: Полная поддержка интерактивных инлайн-меню, callback-запросов и многошаговых мастеров публикации.
- **Персистентные FSM-диалоги в SQLite**: Состояние диалогов `/submitapk` и редактирования заявок сохраняется в таблице `dialogue_state` и переживает перезапуски бота.
- **Отказоустойчивая работа с БД (WAL Mode)**: Журналирование в режиме `WAL` (Write-Ahead Logging) с `busy_timeout(5s)` обеспечивает параллельное чтение и запись без блокировок (`database is locked`) при одновременной работе поллера и пользователей.
- **Экономия квот GitHub API (ETag)**: Поддержка условных HTTP-запросов `If-None-Match: etag` с возвратом `304 Not Modified`, что кардинально экономит лимиты GitHub API.
- **Гранулярный Telegram Rate-Limit Retry**: Изолированная обработка `RetryAfter` для каждого запроса Telegram API отдельно, предотвращающая дублирование отправки медиа/фото при длинных описаниях (changelog > 1024 символов).
- **Каталог кастомных APK-приложений**: Загрузка APK напрямую через бот с автодетектом архитектуры (`universal`, `arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`), ручным выбором и валидацией лимита в 2 ГБ (ограничение Telegram на документы).
- **Двухуровневая модерация**: Уведомления всем администраторам в ЛС:
  - **Репозитории**: `[✅ Одобрить]` / `[❌ Отклонить]`
  - **APK-версии**: `[✅ Одобрить как есть]` / `[✏️ Отредактировать]` / `[❌ Отклонить]`
  - Атомарная обработка исключает конфликты и дублирование действий несколькими администраторами.
- **Система полиморфных тегов**: Добавление, удаление и фильтрация категорий для инструментов и APK-приложений.
- **Доставка APK документами**: файлы отправляются в чат сразу после карточки релиза (пересылка по `file_id` — на сервере бота ничего не хранится); описание приложения/репозитория и обложка выводятся прямо в карточке.

## 🤖 Команды бота (в Личных Сообщениях)

> ℹ️ Все команды и диалоги работают **исключительно в ЛС с ботом** для защиты приватности и предотвращения флуда в группах.

### Публичные команды
| Команда | Описание |
|---|---|
| `/start` | Приветственное интерактивное меню с кнопками быстрого перехода |
| `/help` | Текстовая справка по всем доступным командам |
| `/suggest owner/repo [#теги]` | Предложить GitHub-репозиторий на отслеживание |
| `/mysuggestions` | Посмотреть статус своих заявок (`pending`, `approved`, `rejected`) |
| `/submitapk` | Пошаговый мастер публикации нового приложения или обновления APK |
| `/apps` | Список опубликованных кастомных приложений в каталоге |

### Команды администратора
| Команда | Описание |
|---|---|
| `/admin` | Панель администратора со сводной статистикой и 2x2 меню быстрых действий |
| `/track owner/repo [#теги]` | Добавить GitHub-репозиторий в отслеживание с тегами |
| `/untrack owner/repo` | Прекратить отслеживание репозитория |
| `/addtag owner/repo #tag` | Добавить тег отслеживаемому инструменту |
| `/removetag owner/repo #tag` | Удалить тег у инструмента |
| `/list` | Список отслеживаемых инструментов, версий и прикрепленных тегов |
| `/tags` | Канонический список всех существующих тегов |
| `/pending` | Очередь всех активных заявок на модерацию (репозитории и APK) |
| `/admins` | Список всех администраторов бота |
| `/test` | Отправить тестовую Rich Text карточку релиза в целевой чат/топик |

### Команды владельца
| Команда | Описание |
|---|---|
| `/addadmin <id>` | Назначить нового администратора бота по Telegram User ID |
| `/removeadmin <id>` | Снять права администратора с пользователя |
| `/debug` | Техническая диагностика бота (ID чатов/топиков, состояние базы данных, WAL) |

## ⚙️ Конфигурация

Параметры считываются из переменных окружения или файла `.env` (см. [`.env.example`](file:///.env.example)):

| Переменная | Обязательная | Описание | По умолчанию |
|---|:---:|---|---|
| `TELEGRAM_BOT_TOKEN` | Да | Токен бота от [@BotFather](https://t.me/BotFather) | — |
| `TELEGRAM_CHAT_ID` | Да | ID группы/канала для публикации карточек (например, `-1001234567890`) | — |
| `TELEGRAM_ARCHIVE_THREAD_ID` | Нет | ID темы форума (`message_thread_id`) в супергруппе | — |
| `ADMIN_USER_IDS` | Да | Список Telegram ID админов через запятую (первый становится **Владельцем**) | — |
| `GITHUB_TOKEN` | Нет | GitHub Personal Access Token (увеличивает лимит с 60 до 5000 запр/час) | `""` |
| `TRACKED_REPOS` | Нет | Начальный список репозиториев (`owner/repo1,owner/repo2`) | `""` |
| `POLL_INTERVAL_SECS` | Нет | Интервал фоновой проверки GitHub в секундах | `900` (15 мин) |
| `DB_PATH` | Нет | Путь к файлу базы данных SQLite | `kostubet.db` |
| `DRY_RUN` | Нет | Тестовый режим: публикация без сохранения состояния в БД | `false` |

> ℹ️ При локальном запуске через `cargo run` файл `.env` подхватывается автоматически.

## 🚀 Развертывание (Docker Compose)

```bash
cp .env.example .env   # заполнить переменные
docker compose up -d
```

- Логи: `docker compose logs -f`
- Статус: `docker compose ps`

База данных хранится в named volume `kostubet_data` (внутри контейнера — `/data/kostubet.db`) и **переживает любые пересборки, рестарты и `docker compose down`**. Её удаляет только `docker compose down -v` — никогда не используйте этот флаг.

### 🔄 Обновление бота (с сохранением БД)

Из папки проекта на сервере:

```bash
git pull
docker compose up -d --build --remove-orphans
```

- `--build` — пересобирает образ из нового кода и пересоздаёт контейнер; volume с базой не трогается. Кэш-слой зависимостей в Dockerfile делает пересборку быстрой.
- `--remove-orphans` — подчищает контейнеры сервисов, которых больше нет в `docker-compose.yml` (например, удалённый `kostubet-backup`).
- Миграции БД применяются автоматически при старте бота (идемпотентные `ALTER TABLE`).
- Проверка после обновления: `docker compose ps` (контейнер Up) и `docker compose logs --tail=50` (должно быть «База данных инициализирована: /data/kostubet.db»).

### 🧹 Очистка Docker: мусорные артефакты и «лишние вещи»

Со временем Docker накапливает слои старых сборок, остановленные контейнеры и неиспользуемые образы — это может занимать гигабайты. Посмотреть, что занято:

```bash
docker system df
```

Очистка по возрастанию агрессивности:

```bash
docker builder prune              # только кэш слоёв сборки (Build Cache)
docker image prune                # висячие образы (untagged-слои от пересборок)
docker container prune            # остановленные контейнеры
docker image prune -a             # ВСЕ образы, не используемые запущенными контейнерами
docker system prune               # контейнеры + сети + висячие образы разом
docker system prune -a --volumes  # всё вышеперечисленное + тома (ОПАСНО: удалит БД!)
```

Разово после перехода на v1.0.0 — удалить volume убранного backup-сервиса:

```bash
docker volume ls | grep backup    # найти точное имя, например kostubetgithub_kostubet_backups
docker volume rm kostubetgithub_kostubet_backups
```

Рекомендации:

- Регулярно достаточно `docker builder prune` + `docker image prune` — это не трогает рабочий образ бота и его volume.
- ⚠️ `docker image prune -a` удалит и образ бота, если контейнер остановлен — после него пересоберите: `docker compose up -d --build`.
- ⚠️ Никогда не запускайте `docker system prune --volumes` и `docker volume prune` «на всякий случай»: они сносят неиспользуемые тома скопом, включая `kostubet_data` с базой. Удаляйте только конкретный volume по имени (как выше).
- Локальный кэш компиляции Rust (`target/`, может весить несколько ГБ) чистится через `cargo clean` или точечно `rm -rf target/debug`.

### 💾 Разовая копия БД (опционально)

Регулярный backup-сервис убран как ненужный; при желании снять разовую копию базы (WAL-безопасно, без остановки бота):

```bash
docker run --rm -v kostubetgithub_kostubet_data:/data -v "$(pwd)":/out alpine \
    sh -c "apk add -q sqlite && sqlite3 /data/kostubet.db \".backup '/out/kostubet-copy.db'\""
```

> Точное имя volume покажет `docker volume ls` — оно вида `<имя_папки_проекта>_kostubet_data`.
